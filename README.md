# Nepali News Classifier

An end-to-end Nepali news category classifier: a classical NLP/ML pipeline
(TF-IDF + Logistic Regression) served through a FastAPI backend, with a
React + TypeScript + Tailwind frontend and PostgreSQL-backed prediction
history. Built to run comfortably on an 8 GB RAM laptop with no GPU.

```text
Predicted Category: Sports
Confidence: 91.9%
```

## Features

- Nepali text preprocessing (Unicode normalization, URL/punctuation stripping)
  shared identically between training and inference
- TF-IDF (word 1-2 grams) feature extraction
- Three candidate ML models trained and compared: Logistic Regression,
  Linear SVM (calibrated), Multinomial Naive Bayes
- FastAPI backend with `/api/predict`, `/api/history`, `/api/categories`, `/health`
- PostgreSQL-backed classification history (view + delete)
- React/TypeScript/Vite/Tailwind dashboard with confidence bar, category chips,
  and a history table
- Automated tests: 11 ML pipeline tests + 9 API tests (pytest)
- Docker Compose for backend + frontend + postgres

The FastAPI service and the training pipeline both import the *same*
`ml/src/preprocessing.py` module (via a path import, see
`backend/app/services/preprocessing.py`), so text is cleaned identically at
train time and at inference time.

## Dataset

**16NepaliNews Corpus** — 14,364 Nepali-language news documents scraped from
online Nepali news portals (published from 2015), partitioned across 16
newsgroups. Source: [sndsabin/Nepali-News-Classifier](https://github.com/sndsabin/Nepali-News-Classifier)
(GitHub), licensed **GPLv3**. All article content belongs to its respective
original publishers; this repository only distributes a download script
(`ml/data/prepare_dataset.py`), never the corpus itself.

The dataset is **not committed to this repository** (see `.gitignore`) —
it's ~75 MB as a consolidated CSV. Run the prep script to fetch it locally:

```bash
python ml/data/prepare_dataset.py
```

## NLP Pipeline

```text
Raw Nepali Text
      |
      v
Unicode normalize (NFC) -> strip URLs -> keep Devanagari/Latin/digits only -> collapse whitespace
      |
      v
TF-IDF (word-level, 1-2 grams, max 40,000 features)
      |
      v
Logistic Regression (class_weight="balanced")
      |
      v
Category + confidence
```

## Model Evaluation

Trained on an 80/20 **stratified** split (`random_state=42`) of the cleaned,
deduplicated dataset (14,344 rows after cleaning). Because the classes are
heavily imbalanced, model selection is based on **macro-averaged** F1 (every
category weighted equally), not accuracy or a decision score alone.

| Model | Accuracy | Precision (macro) | Recall (macro) | F1 (macro) | Train time |
| --- | --- | --- | --- | --- | --- |
| **Logistic Regression (selected)** | 0.7431 | 0.6093 | 0.6805 | **0.6100** | 10.3s |
| Linear SVM (calibrated) | 0.7902 | 0.7501 | 0.5164 | 0.5769 | 7.4s |
| Multinomial Naive Bayes | 0.6086 | 0.1865 | 0.1032 | 0.1032 | 4.7s |

Logistic Regression was selected: it has the highest macro F1, meaning it
does meaningfully better than the alternatives on the small categories
(Literature, Education, Auto, etc.) even though Linear SVM has higher raw
accuracy (driven by the dominant "National News" class). Full precision/
recall per class and the confusion matrix are in
`ml/models/training_metadata.json` and `ml/notebooks/figures/confusion_matrix.png`
(generate the latter with `python ml/src/evaluate.py`).

These are the actual measured numbers from this run — nothing here is
invented. Re-running training with the same seed will reproduce them
(modulo minor floating-point/library-version differences).

## Confidence Scores

Logistic Regression natively supports `predict_proba`, so the confidence
returned by `/api/predict` is that model's own calibrated-by-training
probability for the predicted class — not a heuristic. (If a future model
swap uses an SVM without native probabilities, `ml/src/predict.py` falls
back to a softmax over the decision function and this would need to be
called out as an approximation — see the comment in that file.)

## Installation & Running Locally

### 1. Clone and set up Python environment

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # macOS/Linux

pip install -r ml/requirements.txt
pip install -r backend/requirements.txt
```

### 2. Prepare the dataset and train the model

```bash
python ml/data/prepare_dataset.py     # downloads + extracts the corpus (requires unrar)
python ml/notebooks/eda.py            # optional: regenerate EDA charts
python ml/src/train.py                # trains, evaluates, and saves model artifacts
python ml/src/evaluate.py             # optional: confusion matrix + per-class report
```

`unrar` is required to extract the source archive:
`sudo apt-get install unrar` (Linux) or install a Windows RAR extractor and
adjust `prepare_dataset.py` accordingly.

### 3. Start PostgreSQL

Easiest with Docker:

```bash
docker run --name nepali-news-db -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=nepali_news -p 5432:5432 -d postgres:16-alpine
```

Or point `DATABASE_URL` at any PostgreSQL instance you already have.

### 4. Start the backend

```bash
cd backend
copy ..\.env.example ..\.env     # Windows; or `cp ../.env.example ../.env`
uvicorn app.main:app --reload --port 8000
```

Visit `http://localhost:8000/docs` for interactive API docs.

### 5. Start the frontend

```bash
cd frontend
npm install
npm run dev
```

Visit `http://localhost:5173`.

## Limitations

- **Severe class imbalance**: "National News" accounts for ~52% of the
  corpus, while "Literature" has only 16 examples total. Macro F1 (0.61)
  is noticeably lower than accuracy (0.74) as a direct result — small
  categories are the model's weakest point (see the per-class report in
  `ml/models/training_metadata.json`).
- **Domain/label noise**: several categories overlap semantically
  (e.g. "Blog", "Opinion", "Interview" vs. topic-based categories like
  "Sports" or "Economy"), which caps achievable accuracy with a
  bag-of-words model regardless of the classifier used.
- **Code-mixed text**: Nepali news frequently mixes in English words,
  numerals, and transliterated terms; the cleaning pipeline keeps Latin
  characters but does not attempt script-aware normalization beyond that.
- **Dataset recency**: articles are from ~2015-2017; category boundaries
  and topical vocabulary (e.g. new technology terms) will drift over time.
- **Confidence is not guaranteed calibration**: while Logistic Regression's
  `predict_proba` is a genuine model output, no explicit calibration
  curve (e.g. reliability diagram) was evaluated in this project.

## Future Improvements

- Fine-tune a Nepali-specific transformer (e.g. NepBERTa, MuRIL) for
  higher ceiling accuracy, at the cost of needing a GPU
- Nepali-aware tokenization/stemming instead of whitespace+regex tokens
- Address class imbalance with oversampling (e.g. SMOTE on TF-IDF space)
  or a focal loss objective
- Named Entity Recognition to surface people/places/organizations
- Explainable predictions (e.g. LIME/SHAP over TF-IDF features)
- Multilingual classification (Nepali + English code-mixed articles)

## Security Notes

- All secrets/config are read from environment variables (`.env`, never
  committed — see `.env.example`)
- Database access uses SQLAlchemy's parameterized ORM queries (no raw SQL
  string interpolation)
- CORS is restricted to configured origins only
- The API performs text classification only — it never fetches, opens, or
  scrapes URLs a user submits
- Input length and emptiness are validated server-side (`422` responses),
  and unexpected errors return a generic `500` rather than a stack trace
